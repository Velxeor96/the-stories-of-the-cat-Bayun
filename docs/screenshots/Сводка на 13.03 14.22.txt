🔧 КЛЮЧЕВЫЕ ТЕХНИЧЕСКИЕ ФАЙЛЫ
dice.py — модуль бросков
Функция: roll_dice(expression, reason="", difficulty=None) -> dict

Возвращает: {"expression", "reason", "rolls", "modifier", "total", "difficulty", "success", "margin"}

Логика: если difficulty > 0 — определяется успех/провал (успех = total ≤ difficulty), вычисляются степени успеха/провала (margin = разница // 10). Если difficulty = 0 — просто бросок без порога (для урона).

format_roll_result(result) — форматирует результат для отображения. Для успеха добавляет «✅ УСПЕХ», для провала — «❌ ПРОВАЛ».

knowledge.py — RAG-lite
Класс KnowledgeBase:

Загружает все .txt из data/, чанкует по абзацам (пустым строкам), сохраняет {text, source, faction}.

FACTION_KEYWORDS — словари ключевых слов для каждой фракции (tau, eldar, imperium, chaos, orks, necrons, tyranids).

_detect_factions(query) — определяет, к каким фракциям относится запрос.

search(query, top_k=4) — ищет чанки по пересечению слов. Чанки из «правильной» фракции получают бонус ×2 к весу. MIN_OVERLAP = 2 (нужно проверить: планируется поднять до 3, чтобы отсеять мусор).

format_context(query, top_k) — возвращает блок «=== СПРАВКА ИЗ БАЗЫ ЗНАНИЙ ===».

app.py — основной сайт
Использует ChatCompletionRequest, ChatMessage, ChatContentPart, ChatFunctionSpecification, ChatFunctionsTool, ChatTool, ChatFunctionResult.

MAX_FUNCTION_ITERATIONS = 15 — максимум вызовов функций за ход.

TOP_K_KNOWLEDGE = 4 — сколько справок подмешивать.

Function calling: функция roll_dice описана через ChatFunctionSpecification (параметры: expression, reason, difficulty — все обязательные).

Логика хода: enrich_query_with_knowledge(kb, user_text) → добавляет справку → отправляет в GigaChat с tools → если function_call → вызывает roll_dice → возвращает результат через ChatFunctionResult → цикл до финального текста.

Отображение: render_roll показывает броски цветом (st.success/st.error/st.info).

Сайдбар: показывает количество загруженных чанков базы.

clean_data.py — чистка базы
Читает _replacements/replacements.txt (формат: НЕПРАВИЛЬНО|ПРАВИЛЬНО|Комментарий).

Поддерживает # EXCEPT: file1.txt, file2.txt — исключения для следующего правила.

Пустая правая часть = удаление.

Без учёта регистра (восстанавливает регистр: Шурикен→Сюрикен, шурикен→сюрикен).

Создаёт резервную копию в data_backup/.

Ищет дубликаты файлов.

Режим сухого прогона: python clean_data.py --dry-run.

check_clean.py — проверка базы
Проверяет, что определённые слова отсутствуют (с границами \bслово\b, чтобы «Костопев» не находилось внутри «Костопевец»).

Проверяет, что определённые слова присутствуют.

Специальные проверки по файлам (например, «Магос Кейн» должен остаться).

dump_all.py — выгрузка базы
python dump_all.py --outline — оглавление (безопасный режим).

python dump_all.py --preview 300 — первые 300 символов каждого файла.

python dump_all.py --full — полный дамп (может быть большим).

📝 ЧТО НУЖНО СДЕЛАТЬ (ближайшие шаги)
Создать data/general/combat_rules.txt — боевая система Rogue Trader:

Инициатива: 1d10 + Ag bonus

Атака: 1d100 против WS/BS

Dodge: d100 против Ag (стоит Reaction)

Parry: d100 против WS (только с оружием ближнего боя)

Урон: бросок оружия − AP брони

Раны: человек 10-15, космодесантник 20-25, орк 15-20, эльдар 12-18

Создать data/general/weapons.txt — таблицы оружия (в процессе, через промт для нейросети).

Создать data/general/armor.txt — таблицы брони.

Создать data/general/character_sheet_rules.txt — правила листа персонажа:

Характеристики: WS, BS, S, T, Ag, Int, Per, WP, Fel

Бонус характеристики = первая цифра (WS 45 → +4)

Fate Points: 1-3, НЕ 40

Раны: зависят от расы

Поднять MIN_OVERLAP в knowledge.py с 2 до 3.

Дополнить unknown_terms.txt — термины, имена, локации:

Скрап-код, Лингва Диаболис — не существуют
